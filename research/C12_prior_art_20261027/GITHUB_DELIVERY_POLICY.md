# 后续任务的 GitHub 优先交付约定

适用范围：后续新任务提示词与本研究的交接。当前已经运行的任务不因本文自动变更。此文不是自动控制其他会话的程序，也不授权合并、运行别人代码、增加算力或改变仓库可见性。

## 1. 目标

让接收者只凭仓库链接就能找到该任务的交接、代码、测试、结果和必要资产索引，不再依赖某个会话的本机绝对路径。优先使用已有相关仓库；确有隐私或项目边界需要时再使用已有私有仓库，不随意创建很多重复仓库。

## 2. 每项任务一个隔离位置

- 使用独立 task 分支和任务目录，不并发写同一个工作树。
- 不直接覆盖 main，不强推别人的分支，不自动合并 PR。
- 提交完成后给出 commit-pinned 的 HANDOFF 链接、目录链接和 PR 链接。
- 记录基于哪个源 commit 开发，避免不同任务把新旧接口拼在一起。
- 旧交付保持可追溯；更正另作新提交，不偷偷重写失败记录。

## 3. 最小交付结构

每个任务至少包含：

- `HANDOFF.md`：目标、实际完成、未完成、如何复现、下一执行者、资源边界。
- `RESULT.json`：阶段状态、源版本、执行环境、测试/训练/推理实际是否运行。
- 代码、配置与必要小型测试。
- 简明结果表、全部预先固定展示样本或其许可允许的资产入口。
- 文件清单与必要哈希；大资产的获取链接、大小、哈希、访问权限和是否已上传。

不要求为了交付制造大量重复报告。图册、测试日志和配置直接链接，不重复在多个文件粘贴整段正文。

## 4. “所有东西能找到”不等于“所有东西都公开塞进普通 Git”

源码、文档和小型可公开证据进相应仓库。权重、恢复状态、特征缓存或大包使用该项目许可与权限允许的存储机制，并在仓库索引中给出可访问入口；具体采用 Releases/LFS 或其他既有资产位置前，核对工具支持、容量与费用，不静默购买服务。

没有上传的资产标记 `NOT_UPLOADED` 或 `EXTERNAL_ASSET_REQUIRED`，不要伪造下载链接，也不要仅给本机路径却声称跨环境可复现。

任何仓库都不提交密钥、cookie、签名临时凭据或认证环境文件。公开仓库不放未授权的私人截图、源数据、答案集或受限制的论文全文。私有结果继续留私有范围，不因“统一交付”把私有仓库改公开。

合法可分享的输出也需避免把盲测答案与模型输入混在同一输入包里：评价者可以访问真值，模型只读取专门的中性输入目录。

## 5. 状态必须分层

- `CODE_READY`：代码与约定已写好。
- `SYNTHETIC_TESTED`：小型或随机 fixture 已测试。
- `REAL_MODEL_LOADED`：指定真实权重实际加载成功。
- `TRAINED` / `INFERRED`：真实任务确实执行。
- `EVALUATED`：声明的指标和数据范围实际完成。

不能因为 READY.json 存在，就跳过模型、数据、设备与数值合同检查。随机小模型通过不等于真实 0.8B 通过；已知故障可恢复不等于实际用户任务已修复。

## 6. 最终回复格式

一句结论＋三个入口通常足够：

1. 交接文档的固定 commit 链接。
2. 完整任务目录/资产清单。
3. PR 或变更记录。

再用一小段写关键结果和唯一重要阻塞。必须实际读取远端确认上传成功，不以本地 git commit 代替远端验收。

本轮 C12 只把这项约定保存下来；不会回头修改用户已经手动补充的其他任务，也没有向它们自动发送新命令。
