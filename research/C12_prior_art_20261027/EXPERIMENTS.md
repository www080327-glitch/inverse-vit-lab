# 两个可检验的研究问题，而不是两项已证新发明

状态：设计建议，**NOT_RUN**。不启动、暂停、延长或改写任何现有训练。

文献与实现证据见 [REPORT_ZH.md](REPORT_ZH.md) 和 [EVIDENCE_MATRIX.md](EVIDENCE_MATRIX.md)。本文件主要是本项目的实验推理与建议。

## H1：保持原视觉输入接口的低开销连续输出适配

### 1. 精确问题

固定一个已经具备理解能力的 VLM 视觉编码器与原始输入接口，能否用非扩散、无 VQ 的连续输出通路，在有限训练下取得可用生成，同时控制原文字/视觉任务的退化？

单纯冻结编码器、训练 ViT 解码器不是新颖性；两阶段扩展已有 VLM 也不是。值得研究的是一个具体可复验的接口、分布建模或训练机制，能否改善“真实表示可解码”到“语言模型预测表示可解码”的落差，并以更小代价保持旧行为。

### 2. 先分清三种任务

| 任务 | 合法条件 | 输出 | 能证明什么 |
|---|---|---|---|
| 编解码重建 | 目标图片经冻结 E 的完整特征 | D(E(x)) | 编码表示在给定解码器下的可重建性 |
| 有图重画 | 源图经原视觉通路进入语言主干 | 完整自由生成视觉特征，再解码 | 语言主干的图像输入→图像输出适配 |
| 纯文字生图 | 描述或类别，不含目标图/目标特征/目标ID | 完整自由生成视觉特征，再解码 | 条件生成能力；不能要求恢复描述没表达的唯一原图 |

三类图册和分数分开。Teacher-forced 单步/特征损失是诊断，不代替自由生成成绩。

### 3. 最小实验序列

**H1-a 表示检查。** 在同一数据划分、目标像素范围和解码预算下，比较真实 post-merger 特征的线性、小 MLP、tiny/full 解码。pre-merger 可作为信息瓶颈诊断，但其 Token 数与维度不同，应列出适配参数、内存和计算，不能简单称为唯一变量比较。不得使用已标注为验证专用的样本补进训练。

**H1-b 输出接口。** 从同一官方语言快照比较 direct 和 MLP，保持更新范围、数据顺序、有效 batch、归一化、训练样本次数和解码器相同。不要一组 full、一组 last4，再归因于输出接口。先只比较 redraw；描述任务必须有独立训练标记。

**H1-c 分布与失配。** 在基线接口已经能学习后，比较确定性回归与可采样连续头，至少报告真实特征和自由预测特征的差异。候选头可参考 GIVT/EAR；不能把它们的损失数值直接排名，也不能在没有显式密度时伪造 NLL。

**H1-d 针对生成误差的鲁棒性。** RAE 已有普通噪声增强，故必须作为参考。若提出“更贴合自回归预测误差”的扰动或训练机制，先由训练/开发样本估计，不读取封存评估误差调参。比较干净重建、普通独立噪声、相关误差和真实预测表示，并检查是否以严重模糊或输出同质化换取鲁棒性。

### 4. 资源与公平性

不用原始 Qwen 输入接口的方案可以比较，但不能同时声称“完全保留原接口”。源图旁路、追加视觉编码器或大型流主干必须计入参数、推理成本和信息输入，不能和只用固定 post-merger 的小接口混比。

公开完整作者代码不可用时，明确标为 paper-inspired 自己实现，不能宣称完整 Argus/STARFlow2 复现。STARFlow2 作为方法参照不等于当前资源下必须复现其整套大系统。

不要求一步完成所有子实验。先证明一项可靠基线，再一次只改变一个主要机制；本轮已有实验原样完成。

### 5. 评测与可否定条件

- 重建：原生分辨率与显示放大分开；记录全局误差、ROI细节、配对图册。CIFAR插值到256不能充当高分辨率细节真值。
- 生成：完整自由序列；固定 prompts/seeds；类别、布局、明确描述属性与多样性分开；不挑样本。
- 保持：原模型和适配后使用相同模板、模式、输出预算；记录原来答对题的保留率、任务分类退化与原始输出。普通文章 CE 不是指令保持的替代。
- 多 seed 与置信度：资源不足可做探索单 seed，但不能把它包装成稳健普遍结论。

如果 direct/MLP 都只能有图重建，纯文字输出仍无结构，就没有建立文字生图；如果视觉提高但旧行为大幅退化，就没有达到“保持能力”的联合目标。只证明可以移植到一个模型是有用工程结果，方法贡献还需要跨数据或跨接口的增量证据。

## H2：可重新访问的细节库与漏检恢复

### 1. 精确问题

在保留原始像素或高精细特征的前提下，模型是否能根据问题和已有推理状态，以小预算取得关键细节，并在初次路由遗漏时补读？与保留所有视觉特征的稀疏层交互、预先剪枝和外部放大相比，是否有可测优势？

“按问题选区域”本身已有近例。本项目需要限定**何时读取、读取什么、如何恢复遗漏、如何结算全部成本**。这些尚未被我们的主模型验证。

### 2. 基线分组

| 组 | 操作 | 特别注意 |
|---|---|---|
| 全图固定缩放 | 一次读取固定大小全图 | 作为简单基线，不代表最强现有视觉能力 |
| 固定高分辨率切片 | 原图切片、全部编码并输入 | 计入全部编码与主干成本 |
| 问题相关静态剪枝 | 先编码后选视觉Token | 比较 FocusLLaVA/B3 思路；不能把已花编码成本忽略 |
| 稀疏层交互 | 保留完整编码表示，在少数层读取/更新 | VISOR 对应的重要内部基线；不是空间路由 |
| 外部动态放大 | ZoomEye/AdaptVision类工具请求 | 计入多轮调用、编码、传输、答案时间 |
| 拟议内部读取 | 模型中显式细节库、区域路由与补读 | 不能只是把Python裁剪器改名字 |
| Oracle区域 | 用真值框给局部图 | 只作可见性上界诊断，不计自主定位成绩 |

baseline 方法若只移植了部分机制，应命名为 inspired baseline，而不是引用作者完整分数。

### 3. 必须存在的失败集

1. 原生高分辨率里可辨认、缩小后消失的小目标；尺寸至少分多个档位，背景和位置独立变化。
2. 相同粗视图、不同关键细节的成对样本，用来暴露路由器盲点。
3. 显著干扰物比真正目标更亮、更大或更相似的场景。
4. 同图换不同问题，要求读取不同区域；也测试多轮问题变化后能否补取此前未用区域。
5. 图层几何错位与纯视觉细节错觉分别标注，不将已知坐标故障修复当成视觉模型的语义理解。

程序化数据是机制基准，不能独占最终泛化论证；实际截图需要许可、隐私处理和明确标注。目标框与答案仅在评价端，文件名、元数据、同目录真值不能进入模型输入。

### 4. 核算完整成本

至少拆分并报告：

`原图/细节库存储 + 粗图编码 + 全部或选区精编码 + 路由/索引 + gather/传输 + 主干前向/解码 + 外部调用/重读`

如果预先计算了所有高分辨率特征，只能声称减少后续某些层的计算，不能说没有处理未选区域。若原图驻CPU、局部特征上GPU，应记录数据传输和缓存命中。保持整个原图不等于GPU零存储，减少KV也不等于总FLOPs同比下降。

先按真实延迟/峰值内存或匹配调用预算比较，再画准确率—成本曲线；视觉Token数是重要中间量，不是总成本。

### 5. 判定

只有 oracle crop 成功：证明细节可见，未证明自主定位。

只有大量额外裁剪成功：可能是有效工具流程，但未证明更高效或原生架构增益。

只有粗路由选中的区域成功：需要报告漏检率和失败目标，而不只报告条件准确率。

如果在相同预算下，对粗视图歧义和小目标任务的补读明显减少漏检，同时未以固定扫描所有细节作为隐藏代价，则值得继续研究其机制和泛化。是否新颖仍需对最新同类方法继续核查。
