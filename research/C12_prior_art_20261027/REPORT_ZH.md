## 结论先行

两个方向都值得继续，但目前的宽泛表述不足以构成新颖性主张。

- **冻结预训练视觉编码器，再训练 ViT 解码器重建图片**：RAE 已有直接先例。
- **复用既有 VLM 的视觉塔，先建重建通路，再训练原语言主干实现理解与生成**：Argus-Unified 的训练组织高度重合，主要区别之一是它使用量化视觉码。
- **连续视觉表示、非扩散、自回归、保留预训练 VLM 能力**：STARFlow2 已把这些目标组合起来研究，但使用额外的自回归归一化流通路，而不是我们当前的小输出接口。
- **视觉信息保留、只在需要处增加图文计算**：VISOR 已研究模型内部的稀疏图文交互；FocusLLaVA 与近期层级查询剪枝工作已研究问题相关、多尺度选择。

因此，不能把“倒置 ViT”“不用扩散”“按问题放大”“把视觉 Token 放进语言主干”单独写成首次贡献。更有希望的是限定接口、学习目标、容错或读取策略，提出一个现有基线没有解决的可测问题。

**没有检索到完全相同的实现，不等于证明无人做过。本报告不是专利检索或录用判断。**

## 1. 核查范围与证据等级

本轮围绕两个精确对象选读 12 篇原论文的方法及相关实现：

A. 冻结既有 VLM 视觉编码器，用学习到的解码器还原其表示，再使语言主干产生可解码的连续视觉序列，尽量不用 VQ 与扩散。

B. 保留高分辨率细节，根据问题或当前推理状态在模型内部按需读取，避免永久丢弃小目标证据，也避免所有细位置在所有层做全量计算。

论文固定版本、阅读位置和官方代码状态见证据矩阵。另核对 RAE 核心模块、STARFlow 发布说明、ZoomEye 与 AdaptVision 官方入口。没有下载模型权重，没有运行作者代码；作者实验保持 `author_report`，本报告的建议保持 `research_proposal`。

图像核对包括 Argus-Unified 官方 HTML 架构图、VISOR PDF 第 5 页图 5，以及 STARFlow2 PDF 第 3/5 页图 2/3。部分大 PDF 超过网页工具限制，采用可访问的原文 HTML；没有将未查看的图像、未读的完整附录或未验证代码写成已经复现。

## 2. 三组最强重合证据

### 2.1 RAE：我们的第一阶段有明确前例

[RAE，2510.11690v1，§3 与 §4.3](https://arxiv.org/html/2510.11690v1) 将冻结的 DINO/SigLIP/MAE 表示编码器与可训练 ViT 解码器配对。其重建目标包含 L1、LPIPS 与对抗项，后续生成使用扩散。它不是原编码器权重的精确逆。

与我们的区别应写成：尝试已有 Qwen VLM 的具体接口、尤其 merger 前后表示，在小预算和既定能力保持要求下的适配，而不是宣称“第一次把语义视觉塔反过来”。换成 Qwen 或把层数照着镜像，本身通常只是实现选择。

**额外发现：C08 所提的解码器噪声鲁棒训练也已有直接参考。** RAE §4.3 已讨论生成表示偏离真实编码表示，以及噪声增强。当前官方 `src/stage1/rae.py` 的 `noising` 也实现了它。原文 v1 用半正态分布采样噪声幅度；本次读取代码使用 `noise_tau * rand` 的均匀幅度。复现时应固定版本和分布，不能将两者称为逐项相同。

官方代码：[RAE README](https://github.com/bytetriper/RAE/blob/main/README.md)、[rae.py](https://github.com/bytetriper/RAE/blob/main/src/stage1/rae.py)。后者读取 blob：`add53bac5d5862e4cf02478300a5ff9b7bb2086d`。

### 2.2 Argus-Unified 与 STARFlow2：后两阶段也不能只按“大方向”申报创新

[Argus-Unified，2607.25527v1，§3.1–3.2、图 3](https://arxiv.org/html/2607.25527v1) 先在冻结的 VLM 视觉编码器之上训练量化器和图像解码器，再训练由预训练 VLM 初始化的语言主干与接口。理解读取连续特征，生成预测离散视觉码。

这是“先打通视觉重建、再赋予原 VLM 生图能力”的很近的参考。我们的连续、无量化接口确有区别，但不能只把量化器删除，就认定方法贡献已经成立；必须解决被删除的概率建模与采样职责。

[STARFlow2，2605.08029v1，§2–3、图 2/3](https://arxiv.org/pdf/2605.08029v1) 以冻结的 Qwen2.5-VL 通路和可训练 TARFlow 通路交错连接，在连续潜空间进行自回归归一化流建模。视觉表示来自 DINO 系列特征上的 FAE，而非原 Qwen 视觉塔输出的直接反解。

这里的 normalizing flow 是可逆密度变换，不能仅因名称含 flow 就当成扩散或 ODE flow matching；同时，其多通路与局部流计算也不能被省略成一个免费线性头。官方 STARFlow 仓库本次仍将 **STARFlow2 标为 Code TBD**；STARFlow/STARFlow-V 的已发布代码不能冒充 STARFlow2 的完整实现。

官方发布入口：[apple-aiml-research/ml-starflow](https://github.com/apple-aiml-research/ml-starflow)。旧 `apple/ml-starflow` 地址在本次读取中发生仓库迁移，已解析至现地址。README blob：`ff0b36be6dc99a0d14ea9eff16ea3a7bf6c64084`。

### 2.3 VISOR、FocusLLaVA 与层级查询剪枝：内部按需视觉计算不是空白

[VISOR，2603.23495v1，§4.2–4.4](https://arxiv.org/html/2603.23495v1) 的基础方案保留编码后的视觉 Token，用少量交叉注意力读取，并选择部分自注意力层更新视觉表示；样本相关策略选择计算配置。它主要选择的是**哪些层执行更昂贵的交互**，不是直接按空间树重新取得原始像素。

[FocusLLaVA，2411.14228v1，§3.1–3.3](https://arxiv.org/html/2411.14228v1) 已结合区域多尺度压缩与语言中间层内的问题相关筛选。其区域下采样采用多尺度 max-pooling，不应误记成平均池化。

[Hierarchical and Query-Aware Visual Token Pruning，2610.24102v1，§III](https://arxiv.org/html/2610.24102v1) 则在进入 LLM blocks 前，进行样本预算、裁剪预算与细 Token 的查询相关选择。它不是运行到后续推理步骤再向原图补读。

三者分别覆盖“稀疏层交互”“内部文本引导选择”“预先层级查询选择”。我们的潜在区别不能只写“根据问题挑重要区域”，而应精确到：被暂不采用的细节如何留存、何时补读、如何纠正初次漏检，以及完整成本是否更好。

## 3. 连续、统一、非扩散：这几个词需要拆开

GIVT 已研究连续向量的线性输入与 GMM 输出；EAR 已研究随机神经生成头和能量评分；两者主要在学习到的视觉潜空间工作。[GIVT](https://arxiv.org/html/2312.02116v4) · [EAR](https://arxiv.org/html/2505.07812v1)

UniFluid 是连续视觉与离散文本的统一自回归框架，但视觉输出使用逐 Token 扩散头；理解还使用独立 SigLIP 特征。因此“自回归”并不自动代表“完全不用扩散”，也不自动代表输入输出共享同一个原视觉表示。[UniFluid §3–4](https://arxiv.org/html/2503.13436v1)

**本项目建议分开写五个属性：** 表示是否连续、是否量化、单步如何建模分布、是否有独立视觉解码器、语言/视觉是否共享主干。不要用“原生”一个词代替五项可检查设计。

## 4. 两个值得保留的研究问题

以下是建议，不是本轮发现了两项已证明的新发明。详细实验见 [EXPERIMENTS.md](EXPERIMENTS.md)。

### H1：不改原视觉输入接口，能否以小开销学出稳健的连续视觉输出？

限定目标为：固定已有 VLM 编码接口及其输入语义，不额外增加一座大型生成主干；学习可解码的连续输出，同时测量语言与视觉理解保持。

不能只比较 `D(E(x))`。需要同时比较真实表示、模型预测表示及其分布偏移；直接输出与 MLP 是接口基线，不是贡献名称。普通加噪在 RAE 已存在，新的方法若研究针对真实预测误差的训练，则需胜过普通噪声增强，而不是只胜过完全无鲁棒训练。

如果只能完成 Qwen 上的低预算迁移，仍是有用工程成果；是否能形成方法贡献，取决于能否提出机制、消融和跨设置证据，而不是模型名不同。

### H2：可再次访问的细节库，能否在相同总预算下减少小目标漏检？

把原始图像或高精细特征保留为可访问状态，粗选择失误后允许补充读取。重点不是“完全不压缩所有 Token”，而是“暂不计算不等于永久丢失”。

需分别对比：全细节输入、静态剪枝、VISOR 式稀疏层交互、问题相关区域选择，以及 ZoomEye/AdaptVision 式外部重看。只有进入模型计算路径的动态细节请求才能支持“原生内部”标签；外部裁剪仍可作为很强的实用基线。[ZoomEye](https://arxiv.org/html/2411.16044v3) · [AdaptVision](https://arxiv.org/html/2512.03794v1)

重要失败情形：两张高分辨率图片的粗视图相同，但关键细节在不同区域。仅观察相同粗视图与相同问题的确定性路由器，不可能凭空作出两个不同的正确选择。应测试额外信息、探索、回退或不确定性，而不是用 oracle 区域偷偷解决问题。这个论证是信息可辨识性的直接推理，不是本报告的新定理。

## 5. 哪些事情不宜包装成独立创新

- 把 12 层编码器配一个 12 层解码器，或使用线性/MLP 输出层。
- 把 E 冻结、把 D 训练好，再做一次语言适配；已有非常近的分阶段方法。
- 只改变模型型号、数据集或参数量，而没有新的机制或一致结论。
- 只增加裁剪次数、视觉 Token 或总计算量，然后声称注意力机制更强。
- 使用真实源图旁路、验证特征或目标图位置信息，却将重建写成自由生成。
- 用合成任务证明复杂度/数值路径后，直接推导大模型质量、吞吐或 AGI 能力。

这不意味着这些工作不值得做。它们是建立基线、定位问题和复现的重要步骤，只是论文主张需要与证据层级一致。
