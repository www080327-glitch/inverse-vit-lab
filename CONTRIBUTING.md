# Contributing

1. Open an issue describing one research question, the evidence already available, and the smallest experiment that could change the conclusion.
2. Work on a topic branch and open a pull request to `main`.
3. For code changes, run the no-download CPU check. If your change needs data, model weights, or an accelerator, state the extra requirements and keep a small synthetic test where possible.
4. For comparisons, publish the split, seeds, checkpoint rule, sampling settings, stopping rule, and failures alongside any claimed improvement.
5. Do not commit model weights, optimizer/checkpoint state, raw datasets, private logs, credentials, cookies, SSH material, platform/account identifiers, bills, personal details, or local absolute paths.
6. Do not upload third-party papers, abstracts, or text collections. Link to the source and preserve its terms instead.
7. Never claim a passing visual result from teacher-forced reconstructions, a classifier score, selected samples, or a tiny smoke run.

Use GitHub issues for research questions and pull requests for reviewable changes. Do not assign issues to another person unless they volunteer.
